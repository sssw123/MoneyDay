# PRD: 未实现目标预计实现时间推算与心愿单/长期目标双轨管理

## 目标与价值
1. 为未实现目标提供动态「预计实现时间」预测，让用户清晰预见按当前的财务节奏何时能达成目标。
2. 明确划分【心愿单 (Wishlist)】与【长期资产目标 (Long-term Target)】：
   - 心愿单记录随缘消费，不占预留资金，实现看心情；由日常累计结余池提供达成参考；
   - 长期资产目标由用户总资产（可用净资产）托底，由每周期净沉淀推进；
3. 具备超支保底机制，在用户历史结余为负时给出“若严格执行模板预算”的理论时间，起到理财指导和正向激励作用。

## 核心业务规则 (严格对齐 CONTEXT.md)

### 1. 目标双轨定义
- **心愿单 (WISHLIST)**：
  - 适用场景：数码产品、心仪服饰、旅游等软性心愿消费。
  - 资金特性：**不占用任何预留资金**，不锁定总资产。
  - 参考资金源：全局累计结余池（`cumulativeBalance`）。
  - 资金缺口：`max(0, targetAmount - cumulativeBalance)`。
  - 存钱速度 (Velocity)：
    - 正常：历史已结算周期的平均实际结余（若 > 0）。
    - 超支保底：当前模板【周期基准结余】（`固收 - 固支 - 固存`）。
  - 达成规则（软警告二次确认）：
    - 只要所选扣款账户余额足够即可兑现；
    - 若累计结余不足（`cumulativeBalance < targetAmount`），给出软警告确认提示（“将导致结余超支”），用户确认后仍可记账实现。
- **长期资产目标 (LONG_TERM)**：
  - 适用场景：大件储备、买车买房、大额理财等资产储备。
  - 资金源泉：可用净资产（当前阶段即为全部账户总资产）。
  - 资金缺口：`max(0, targetAmount - totalAssets)`。
  - 存钱速度 (Velocity)：
    - 正常：【每周期净沉淀】 = `周期固存 + 历史实际平均结余`。
    - 超支保底：基准净沉淀 = `周期固存 + 模板基准结余` = `固收 - 固支`。
  - 达成校验：实现目标时，强校验 `totalAssets >= targetAmount` 且扣款账户余额充足。

### 2. 独立标尺原则 (Independent Benchmark)
各目标不参与资金竞争排队，各自独立评估达标距离。

### 3. 达成时间推算
- `neededCycles = ceil(资金缺口 / 存钱速度)`。
- 从当前账单周期向后顺延 `neededCycles` 个周期，取该周期的结束日期作为预计实现时间。
- 若存钱速度 <= 0，显示“无法预估”。
- 若资金缺口 <= 0，显示“当前可实现”。

### 4. 前端展示规范
- 【攒钱目标】页面：
  - 表单支持选择目标类型：【心愿单】 vs 【长期资产目标】。
  - 表格新增「类型」标签（心愿单 / 长期资产）与「预计实现时间」列。
  - 保底推算时显示橙色提示 Tooltip。
  - 点击实现心愿时，若结余不足，弹出友好确认提醒。
- 【首页看板】页面：
  - 快捷实现表格同步展示「类型」与「预计实现时间」。

## 验收标准
- [ ] 数据库 `target` 表支持 `type` 字段（`WISHLIST` / `LONG_TERM`）。
- [ ] 后端计算逻辑中，长期资产目标的可用资金等于总资产，心愿单不扣除总资产。
- [ ] 心愿单在结余不足时允许通过二次确认兑现，且真实扣除账户余额。
- [ ] 预计实现时间双轨推算准确，超支保底逻辑完整生效。
- [ ] 前端界面全面统一“心愿单”概念，无歧义文案。
