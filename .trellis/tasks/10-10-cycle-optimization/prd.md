# 周期与目标优化 (Cycle Optimization and Fixed Deposit)

## 目标 (Goal)
将“预算与目标”页面的展现形式由单调的预算列表改造为“周期表”，以清晰展示每个周期的结余和超支状况；同时引入“必攒金额（固存）”概念，使资金进度展示更加符合强制储蓄的理念。

## 已知事实 (Confirmed Facts)
- 当前有 `Budget` 表，后端需保留其 API 接口，但前端彻底移除“预算管理”设置页面。
- 当前周期是通过 `CycleTemplate`（默认模板）以及当前日期计算得出的。
- 事务分为收入、支出、转账。目标包含目标金额和已分配金额。

## 需求 (Requirements)
1. **取消预算管理 UI**：在“预算与目标”页面前端移除现有预算设置 UI。
2. **新增周期表概览**：以列表/表格的形式，展示各个周期的资金概况（周期起止时间、总收入、总支出、固存、结余）。结余为正或零显示为绿色，为负（超支）显示为红色。
3. **新增固存（必攒金额）功能**：
   - 允许在“周期模板”配置中设置全局默认的“固存金额”。
   - 采用**快照固化机制**：当周期首次产生数据或被访问时，将全局固存金额落库存入独立的周期记录（`CycleRecord`）中。后续修改全局模板不影响历史已固化的周期快照。
   - 允许用户在“周期表”中对特定周期进行单独的固存金额修改覆盖。
4. **重新定义进度公式**：
   - **可支配收入** = 该周期总收入 - 固存。
   - **周期结余** = 该周期总收入 - 固存 - 该周期总支出。
5. **目标流转规则**：
   - 目标（Target）在平时的分配和进度更新只是“预期设定”，不从当期实际结余中扣除。
   - 仅当用户在目标页面显式点击“实现目标”时，才产生实际的资金扣除（转化为具体支出）。

## 验收标准 (Acceptance Criteria)
- [ ] 前端“预算与目标”页面不再显示预算设置模块，取而代之的是包含多个周期的“周期表”。
- [ ] 周期表中正确显示周期区间、收入、支出、固存和结余，且红绿颜色标识正确。
- [ ] 修改 `CycleTemplate` 的全局固存默认值，只有新产生的周期采用新值，历史周期的固存金额保持不变。
- [ ] 允许在周期表中点击修改某一个历史/当前周期的固存，修改成功后，该周期的结余重新计算。

## 暂出范围 (Out of Scope)
- 历史 Budget 表数据的迁移与清理（保留数据和接口）。
