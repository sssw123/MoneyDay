# 技术设计与架构边界

## 核心架构
- **前端**：Vue 3 + TypeScript + Vite + Vue Router + Pinia，UI 框架采用 Ant Design Vue。采用响应式设计，优先适配手机端浏览。
- **后端**：Java 17 + Spring Boot 3.x，提供 RESTful API，统一 `/api` 前缀。
- **数据存储**：MySQL 8.0。数据库表由后端配合 MyBatis 进行管理，并使用迁移脚本进行版本控制。

## 数据模型边界
1. **User (用户)**：单用户自用，基础用户表。
2. **Account (账户)**：基础账本实体（名称、类型、当前余额、期初余额）。
3. **Category (分类)**：收支分类，支持层级（如果需要）和启用/停用状态。
4. **Transaction (账单流水)**：核心记录，包含收、支、转账。外键关联 Account 和 Category。
5. **Target (攒钱目标)**：目标金额、已分配金额、截止日期。全局关联，不绑定具体账户。
6. **CycleTemplate (周期模板)**：支持多模板管理（如发薪日模板、自然月模板），包含起算日（1-31）及是否默认。

## 关键技术决策与权衡
- **自定义账单周期 (Custom Billing Cycle)**：不再通过复杂硬关联，而是建立独立的 `CycleTemplate` 表进行管理。统计查询 API（收支聚合、预算进度）在后端读取当前 `is_default=1` 的模板，并结合当前自然时间和起算日（遇到月末智能处理，如 31 号自动适应小月的 30 号），动态推算出本周期的 startDate 和 endDate 进行数据过滤，从而统一全局时间口径。
- **金额精度**：采用 `DECIMAL(18,2)` 和 `BigDecimal` 避免浮点误差，接口传输使用 `String`。拒绝多余小数，不进行静默舍入。
- **时区处理**：系统强绑定 `Asia/Shanghai` 时区，前后端统一，避免跨时区算账导致预算漂移。
- **目标透支 (Global Target Overdraft)**：容忍 `SUM(Account.balance) < SUM(Target.allocated)` 的状态出现。采用最终一致或每次计算的形式展现警告，不阻断核心记账写入（在写入 Transaction 时不做强一致的目标余额校验，仅触发页面提示）。

## 交互设计说明
- **表单输入**：支出金额默认为正数输入，后端自动按减项处理。
- **数据联动**：编辑或删除历史流水时，需触发相应账户余额的重算。为保证性能，可采用在现有余额上进行 Diff 加减的逻辑。
