# 记账与攒钱系统 MVP (Phase 1) 需求与验收标准

## 目标与核心价值
完成个人自用日常记账与攒钱闭环（记录钱从哪里来、花到哪里去，了解账户余额与每月预算，并持续跟踪攒钱目标）。

## 确认的事实与上下文
- **受众**：个人自用，不开放公众注册，单用户系统。
- **技术栈**：前端 Vue 3 + TS；后端 Java 17 + Spring Boot；数据库 MySQL。
- **核心记账规则**：
  - 默认币种 CNY，时区固定为 `Asia/Shanghai`（中国北京时间），前后端与数据库统一以此为准。
  - 金额底层用 `BigDecimal` / `DECIMAL(18,2)`，接口用字符串，必须大于 0，禁止静默截断。
  - 收入增余额，支出减余额。期初余额不计入当月收入。转账不计入收支。
  - 攒钱目标是对现有账户资金的“用途分配”，存入/取出目标不会改变总资产和收支。
  - 关联约束：所有对记录的增删改必须与余额、预算、目标强一致，开启事务回滚。

## 需求项 (In Scope)
1. **登录与个人设置**：登录/登出，修改密码。
2. **账户管理**：增删改查手动维护的账本（现金/银行卡等），期初/当前余额，账户转账。
3. **分类管理**：收支分类自定义，可停用（代替硬删除以保留历史记录关联）。
4. **收支记账**：手动录入收支明细（金额、日期、分类、账户、备注），支持修改删除并同步联动计算。
5. **预算与周期**：支持新增多个自定义记账周期/模板（起算日范围为 1-31，31 代表月末），并可自由设置某一个为默认模板，首页及统计将根据默认模板展示周期内的已花、剩余与超支情况。
6. **攒钱目标**：设定目标金额及截止日，记录存入/取出。**限制**：目标资金不再绑定单一账户，而是由全局【总资产】统一托底。优先保证日常记账流水的真实记录。当全局记账导致总资产小于所有目标资金合计时，**不拦截记账**，允许系统进入「全局目标透支」状态，前端辅以红色警告。
7. **首页与统计**：依据自定义的记账周期模板进行展示（如周期内总收支平衡、账户总资产、预算进度、分类占比与趋势），保证每次进入页面时统计口径一致。

## 非需求项 (Out of Scope)
- 多用户共享账本、外部银行/支付平台的自动账单抓取、投资理财计算、多币种转换、PWA 或原生移动 App。
- 账户停用功能及历史归档（MVP 阶段暂不实现，账户暂时只支持增删改查）。



## 验收标准 (Acceptance Criteria)
- [x] 账户功能：能够成功添加、修改不同类型账户（如银行卡、微信等），并正常显示当前余额。
- [x] 记账功能：能够准确记录收入、支出和转账，每次增删改查操作后，相关账户余额必须自动更新且精准无误。
- [x] 目标功能：在全局总资产小于目标已分配资金总和时，系统不阻止日常记账操作，但在页面明显位置显示“全局目标透支”警告。
- [x] 个人设置：支持用户修改自定义账单周期/发薪日起算日。
- [x] 时区处理：记账日期与时间严格遵循 `Asia/Shanghai` 时区，不受客户端物理时区干扰。
- [x] 统计功能：首页能够正确渲染月度总收支、资产总额与预算结余。
