# PRD: 目标按累计结余自动推进与实现

## 目标与价值
将「攒钱目标」的进度由手动填写的「已存金额」彻底重构为**由全局「累计结余」自动驱动**。
- 【已存金额】字段废除。
- 新增【开始时间】作为目标的立项时间标识。
- 全局建立「累计结余池」（历史所有周期结余之和），目标的推进进度直接反映累计结余与目标金额的比值。
- 当累计结余达到或超过目标金额时，方可点击「实现目标」；未达标严禁实现。
- 实现目标时，生成支出交易并扣除所选账户余额（该支出自然计入周期支出，自动完成结余的物理扣减）。

## 详细功能需求

### 1. 数据结构升级 (Target 实体与表)
- **删除字段**：`allocated_amount`（数据库表中删除，实体类中移除）。
- **新增字段**：`start_date` (LocalDate)，可自定义，默认创建时间（当前日期）。

### 2. 累计结余池计算
- **公式**：`累计结余 = 所有周期的周期结余之和`。
- 因为实现目标生成的支出交易会自动进入周期支出并冲减周期结余，因此历史所有周期结余之和即为当前的实时净累计结余。
- 提供接口返回当前全局累计结余金额（例如在 `/targets/stats` 或在每个 Target 返回对象附带当前全局累计结余）。

### 3. 目标进度与实现控制
- **目标进度展示**：
  - 如果目标已实现（`isRealized == 1`）：进度展示为 100%（或已实现状态）。
  - 如果未实现：
    - `progress = Math.min(100, Math.max(0, Math.round((累计结余 / targetAmount) * 100)))`。
- **实现条件控制**：
  - 前端：若 `累计结余 < targetAmount`，禁用「实现目标」按钮并提示“累计结余不足”。
  - 后端：在 `realizeTarget(id, accountId)` 中做强校验：如果 `当前累计结余 < target.getTargetAmount()`，直接抛出业务异常拒绝操作，严禁越界实现。

### 4. 实现目标的扣款流转
- 用户点击可用的「实现目标」按钮。
- 弹窗选择扣款账户。
- 确认后：
  1. `target.isRealized` 置为 1。
  2. 生成真实支出流水（`type = 2`, `amount = target.targetAmount`, `remark = "实现目标：" + target.name`）。
  3. 扣除对应账户余额。
  4. 该支出在当前周期产生扣除，从而当期结余相应减少，实现对全局累计结余的扣减。

## 验收标准
- [ ] 数据库表 `target` 删除 `allocated_amount` 字段，新增 `start_date` 字段。
- [ ] 前端目标表格删除「已存金额」列，新增「开始时间」列。
- [ ] 前端新建/编辑目标弹窗移除「已存金额」，新增「开始时间」日期选择（默认当天）。
- [ ] 目标进度条根据 `累计结余 / 目标金额` 动态计算。
- [ ] 累计结余不足目标金额时，「实现目标」按钮禁用；后端接口强制拦截并报错。
- [ ] 满足条件实现目标后，账户余额扣除，当期产生支出，累计结余自动扣减。
