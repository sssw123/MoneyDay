# Git Commit 规范契约

> **契约/规定**：本项目中所有 Git Commit 提交信息，必须遵循 **`<type>: <中文描述>`** 的格式。

---

## 1. 提交格式要求

Commit message 标准格式：
```
<type>: <中文简明描述>

[可选的详细正文描述]
```

## 2. 常用 Type 前缀定义

| Type 前缀 | 适用场景 | 示例 |
| :--- | :--- | :--- |
| **`feat`** | 引入新功能 / 新特性 | `feat: 增加定时任务引擎与待办中心` |
| **`fix`** | 修复 Bug / 异常逻辑 | `fix: 修复提前还款期数计算与扣款逻辑` |
| **`refactor`** | 代码重构（不改变外部行为，如删除废弃字段/表） | `refactor: 清理目标表与用户表冗余字段，移除已废弃的 budget 表` |
| **`docs`** | 文档更新（如 PRD、Design、Implement、规范文档） | `docs: 补充待办中心接口技术设计文档` |
| **`style`** | 代码格式调整（空格、分号、排版，不涉及业务改动） | `style: 统一前端卡片间距样式` |
| **`test`** | 新增或修改测试用例 | `test: 增加调度引擎与待办生命周期集成测试` |
| **`chore`** | 构建过程、辅助工具、依赖变动等杂项 | `chore: 升级依赖版本` |

## 3. 执行约束

1. **类型小写**：Type 前缀一律使用小写字母（如 `feat`、`fix`、`refactor`）；
2. **冒号后空格**：冒号后保留一个英文空格（如 `feat: `）；
3. **中文描述**：描述部分必须为中文，清晰直观地表达本次提交解决的问题或交付的价值；
4. **AI 与开发者通用**：无论是 AI 助手（如 Antigravity、Codex）还是人类开发者，在此项目中执行 `git commit` 时必须严格遵守此规则。
