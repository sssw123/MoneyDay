# Flutter 功能对照与切换清单

此清单对照现有 `frontend` 和 `android-frontend`，记录 Flutter 实现与业务验收边界。实现源码存在不等于已连接真实后端验证；以下各项初始状态均为**待业务验收**，由验收人附日期、平台、后端版本和证据后更新。

## 不可放宽的回归点

- 用户 A 的迟到成功、错误、取消后响应不得覆盖用户 B；已打开的旧表单不得以新会话提交。
- HTTP 状态和响应体 `code` 都需要成功，401/403 应触发当前会话检查；强制改密期间无法访问业务页面。
- 财务写入没有自动重试；断网、超时或响应丢失后提示结果未知，刷新核对再手动操作。
- 心愿超支确认不放宽扣款账户余额限制；长期目标保留净资产门槛，服务器最终再次校验。
- 固定项目只能记账一次；撤销恢复原账户余额，负债提前还期后自动代扣不能重复。
- 原有后端、Web、Android 的测试和构建继续通过；不得为了迁移改写服务器账务规则。
- Android 不初始化、读取、迁移或删除历史 SQLite；共存预览不能覆盖旧 `com.moneyday.app`。

## 六端运行验收步骤

在每个平台记录 [验证表](validation.md)，不能以一个平台的结果代替其他平台：

1. 在目标宿主构建并启动目标平台应用，记录 SDK、OS、设备、Git SHA、后端版本和 API 地址（不含令牌）。
2. 使用管理员分配的专用测试账户登录，验证改密、退出/再登录以及普通用户路由限制。
3. 读取账户、周期和看板；新增一笔小额测试收入/支出，刷新后逐项核对流水、账户余额及看板变化，再撤销测试流水并核对恢复。
4. 使用同一后端的旧 Web 读取该账本核对结果，确保无需客户端迁移或同步。
5. 验证转账、固定到账/撤销、心愿超支和目标资产门槛、负债提前还期/结清、待办补扣，以及断网后不重放写入。
6. 在手机/平板/桌面、横屏、窄窗、键盘弹起、空数据及错误状态检查布局与操作。

真实后端集成测试会写入并清理专用测试账本；它不能代替上述逐端运行、布局和设备验收。不得用个人或生产账本运行写入测试。

## 切换门槛与过程

切换负责人必须确认：功能表全部验收；六端构建及运行通过；后端与旧客户端回归通过；正式 API HTTPS 可用；生产 Android 原签名和递增版本号已核对；Web 深链接与 `/api` 代理部署配置已验证。任何一项缺证据都维持旧默认入口。

1. 保存旧 Web 静态产物、旧客户端安装包、部署配置及发布版本。备份数据库仅用于灾难恢复，不作为常规客户端回退。
2. 用独立地址/独立包 ID 分发 Flutter 预览，验证同一云端账本、权限及六端功能。
3. 形成带证据的验收记录后，Web 将默认静态入口切到 Flutter；Android production 使用 `com.moneyday.app`、原签名及高于已发布版本的构建号。其他平台按目标环境签名/安装流程分发。
4. 发布后观察登录失败、401/403、接口失败、结果未知写入、重复流水和对账差异；出现异常时立即停止扩大发布，先刷新核对服务器账本。

## 回退与数据保留

- Web 恢复上一版静态资源和原路由配置，保留 `/api` 指向相同后端。
- 共存预览直接停止使用 Flutter preview，启动旧客户端；无需导入或删除任何本地财务数据。
- 已发布 production 的 Android 不强行安装更低版本。需要回退时使用原签名构建带更高版本号的旧客户端，并单独验证兼容性。
- 保留已产生的有效云端流水；客户端回退不回滚数据库，也不删除无法确认的财务写入。
- 旧版源码删除与商店发布另行处理；本次不删除两个旧前端目录，不改变默认入口。
